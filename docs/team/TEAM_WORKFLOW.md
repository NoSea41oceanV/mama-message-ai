## 1. 全員が共有する結論

今回完成させるのは、次の一連のデモです。

> 家庭で保護者同席のもと利用する3〜6歳の未就学児へ、保護者同意済みの素材を使い、その場にいない保護者からの短いAIビデオメッセージを届ける。

プロダクト全体は母親専用ではありません。母親からの `Mama Movie` は主デモ上の例として残します。「本物の保護者がリアルタイムで話している」とは表現しません。また、「駄々をこねる子を黙らせる」のではなく、その場の父親・母親・祖父母などが寄り添う際の気持ちの切り替え補助として扱います。OrcaRouterは、通常返信、動画生成、安全対応を振り分ける判断役として実際の処理に組み込みます。

## 2. MVPの完成ライン

次の2シナリオが、デモ環境で繰り返し動けばMVP完成です。

### 成功シナリオ

母親が仕事中、父親と過ごしている子どもが、嬉しかったことや寂しい気持ちを声で伝える場面を主デモにします。父親はその場で操作を補助し、子どもの気持ちに寄り添います。

1. 子どもが大きなマイクボタンをタップして録音を始める。録音中は波形、経過時間、「きいているよ」を表示する。
2. もう一度マイクボタンをタップして止め、音声認識された「ママ、今日ブロックでおうちを作ったよ」を確認して「おくる」を選ぶ。
3. OrcaRouterが `generate_mama_movie` に分類する。
4. 短いテキストの即時返信を表示する。
5. 動画生成中の表示へ進む。
6. 5〜8秒のビデオメッセージを再生する。
7. モデル、原価、レイテンシ、ルートをログで確認できる。

### 安全シナリオ

1. マイクで深刻な不安や危険を示す発言を録音し、認識テキストを確認して「おくる」を選ぶ。
2. `safety_escalation` に分類する。
3. 保護者からの動画を生成しない。
4. その場にいる父親・母親・祖父母など、信頼できる大人への相談案内を表示する。
5. 保護者が確認すべきログとして残す。

音声入力が使えない場合は、子ども向け文言でマイク許可または再録音を案内します。復旧できない場合だけ文章入力へ切り替え、デモを継続します。

### シチュエーション展開

父親との留守番、就寝前、出張・単身赴任、祖父母の預かり、保育園から帰宅後の成功体験、誕生日・発表会、一時的な入院・別居を想定します。保育園内で子どもが自由に利用する形はMVP対象外で、見守り・同意の設計を伴う将来展開です。

## 3. AI実行・人間レビュー型の体制

開発実装、テスト、資料作成、記事作成、提出準備はCodexが担当する。人間3人は、短時間のレビュー、意思決定、外部公開の承認を行う。

### Codex: 実行担当

- アプリの実装、統合、テスト、修正
- OrcaRouter、動画連携、安全分岐、ログ
- README、PowerPoint、Qiita/Zenn記事、デモ台本の作成
- 提出URLとGoogleフォーム入力内容の準備
- レビュー時に、変更点・動作・未決事項を短く提示

完了条件: 人間が判断すべき項目以外は、確認可能な成果物まで自律的に仕上げる。

### 主レビュアー: 判断・承認責任（人間レビューの約70%）

- プロダクト名、対象ユーザー、表現、安全方針の最終判断
- 動くMVP、デモ動画、記事、提出内容のレビュー
- スコープ変更と外部公開の承認
- Googleフォーム最終送信の承認

### レビュアーA: 体験・安全確認（約15%）

- 子ども向け文言、画面の分かりやすさ
- 成功シナリオ、安全シナリオの妥当性
- 母親本人だと誤認させない表現の確認

### レビュアーB: 伝達・提出確認（約15%）

- 3分動画とQiita/Zenn記事の伝わりやすさ
- README、提出URL、公開権限の確認
- Googleフォームの送信前チェック

レビューは原則10〜15分で、Codexが提示する成果物に対して「承認」「修正点」「保留」のいずれかを返す。人間へ実装作業を割り当てない。

## 5. GitとCodexの運用

### 共有の中心

チーム間の正本はGitHubリポジトリです。Codexがコードと文書を更新し、人間の判断はリポジトリ内の決定記録へ反映します。

### 作業ルール

1. Codexが作業前に `main` の最新状態を確認する。
2. Codexは `feature/core-mvp` で実装し、レビュー可能な単位にまとめる。
3. Codexが変更内容、確認方法、残課題を提示する。
4. 主レビュアーが承認または修正点を返す。
5. 承認後にCodexが `main` へ反映する。
6. APIキー、個人情報、保護者素材はGitへ入れない。

### Codexの使い方

- このCodexタスクを実行の中心とし、PRDと進行資料を継続的に参照する。
- 並行作業が必要な場合はCodexの別タスクまたはGit Worktreeを使う。
- 人間レビューが必要な時だけ、確認対象と判断事項を短く提示する。
- APIキー、保護者素材、実在の子どものデータをCodexタスクやGitへ貼らない。
- GitHub公開、YouTube公開、Qiita/Zenn公開、Googleフォーム送信は承認を得て実施する。

## 6. 担当間の接続契約

AI処理の結果は、最低限次の形に揃えます。実装言語が変わっても、キー名と意味を共有します。

```json
{
  "route": "generate_mama_movie",
  "instantReply": "すごいね！どんなおうちを作ったの？",
  "movieMessage": "すごいね。ママはいつでも応援しているよ。",
  "safetyMessage": null,
  "requestLog": {
    "model": "selected-model",
    "cost": 0,
    "latencyMs": 0,
    "status": "success"
  }
}
```

動画処理は `pending` / `completed` / `fallback` / `failed` の4状態を返します。

## 7. 15分ルールと統合ルール

- API接続で15分詰まったら、モックまたは固定動画へ切り替えて全体を先に通す。
- 音声権限拒否・認識失敗でデモが止まりそうな場合は、再試行案内を確認したうえで文章入力フォールバックへ切り替える。
- 2時間ごとに `main` へ統合できる小ささへ分ける。
- 統合時は成功シナリオを毎回通す。
- 壊れた状態を `main` に残さない。
- 仕様変更は口頭だけで済ませず、この資料またはPRDへ1行でも記録する。
